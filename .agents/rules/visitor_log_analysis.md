# 访客日志分析规范与防踩坑军规 (Visitor Log Analysis Guidelines)

在对 ShipAny Video Lite 新用户访问、访客日志、转化漏斗进行数据提取与分析时，**必须严格遵守以下军规，杜绝将网络爬虫、SEO 机器人与自动化探针误判为真人访客**。

---

## 🚫 严禁采纳的虚假“真人”判定指标（踩坑教训）

1. **绝对不能单纯以“是否加载了静态资源（JS/CSS/Video 封面）”判定为真人**：
   - 现代搜索引擎（如 Googlebot、Bingbot）及无头浏览器抓取器在索引 SPA（单页应用）时，会自动并发下载所有 JS/CSS 脚本，甚至探测视频封面海报。
2. **绝对不能单纯以“URL 携带了 utm 推广标签”判定为真人**：
   - 国际 SEO 分析爬虫（如 **AhrefsBot**、Semrush、DotBot）在爬取博客（`/blog/`）或模型对比页（`/models/*`）时，会自动顺着文章内部所有的 `<a>` 标签跟踪爬取（如 `/sign-up?utm_source=blog_cta&utm_campaign=video_generator`），产生海量完全由爬虫制造的虚假外链跳转。
3. **绝对不能将固定接口探针误判为真人**：
   - 自动化探针：单次/周期性请求 `/api/auth/session`、`/api/health`；
   - 资源探测蜘蛛：只请求 `/favicon.svg`、`robots.txt`、`sitemap.xml`、`/.git/`、`/.env`；
   - 单页秒退（Single-Hit）：无后续动作一律归为爬虫或跳出流量。

---

## ✅ 真实人类用户（Genuine Humans）的硬核判定标准

分析访客日志时，判定为“真实人类用户”必须满足以下**强交互信号之一**或**多维交叉验证**：

### 1. 核心强交互信号（满足任一即确认真人）
- **身份鉴权行为**：
  - 发起真实的 OAuth 授权并产生有效回调（携带合法 `code` 与 `state`，如 Google / GitHub OAuth）；
  - 成功完成账号注册或登录流程，在 `user` 表产生新增记录。
- **AI 视频核心业务动作**：
  - 在视频生成器中实际触发了视频/图像生成（`POST /api/ai/generate` 或在 `ai_task` 表产生任务）；
  - 在控制台创建或轮询了任务（`/my-creations`）；
  - 在设置中心生成了 API Key。
- **钱包与付费行为**：
  - 进入 `/pricing` 并触发支付渠道选择，或调起第三方收银台（Stripe / PayPal / Waffo / Creem）；
  - 数据库 `order` 或 `subscription` 表中产生有效订单。

### 2. 未登录潜客的严格准入过滤（漏斗顶层新客判定）
对于尚未登录的新访客，若要判定为“真实人类探索者”，**必须同时满足**：
- **IP 归属清洗**：排除数据中心与 SEO 爬虫 ASN（如 Ahrefs Pte Ltd, Google LLC, Censys, Shodan, DigitalOcean, AWS 机房等）；
- **有时序的人类浏览轨迹**：具备典型的人类操作延迟（如落地模型页 ➔ 停留 15s 阅读 ➔ 点击 Pricing ➔ 停留 20s 比对），而非 1 秒内机械抓取多页面；
- **非单页秒退**：必须具备真实页面跳转交互。

---

## 🔍 必须执行的数据库（Ground Truth）强制交叉校验

在汇报任何“高意向访客”或“转化趋势”前，**必须强制执行数据库对照查询**：
1. 若日志显示大量“注册点击”，但 `user` 表过去 24 小时新增记录为 0 ➔ **必须立即核查是否是 AhrefsBot 等爬虫在爬取超链接，或注册链路存在报错拦截**；
2. 若日志显示大量“结账调起”，但 `order` 表无对应订单 ➔ **必须区分是真实用户卡在发卡行 3DS 拒付环节，还是网络爬虫在探测支付路径**；
3. 区分**老用户日常创作**与**新访客获客**，不可将老用户的日常生成混淆为新获客意向。
